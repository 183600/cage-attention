# Bug audit scratchpad

## Confirmed: complex tensor scalar leaks RuntimeError

`float(torch.tensor(0.1+0.1j))` raises
`RuntimeError: value cannot be converted to type double without overflow`.
Validation paths documented to raise `ValueError` / abstain only catch
`TypeError, ValueError, OverflowError`, so the exception type leaks.

- `cage/data.py`: `time_ordered_split` / `group_disjoint_split` fractions.
- `cage/model.py`: `Cfg.__post_init__` `layer_scale`, `dropout`,
  `calib_a`, `calib_c`, `calib_scale`, `calib_tau_init`.
- `cage/train.py`: `train_model` `log_every`, `eval_every`.
- `cage/experiments.py`: `Settings.__post_init__` numeric fields
  (`depth_step_multipliers`, `dropout`, `negative_control_tol`, `lr`,
  `overfit_lr`, `fdr_q`, `design_alpha`, `power_target`), plus
  `curve_points` validation in the runner and design-plan alpha/target.
- `cage/metrics.py`: `_bootstrap_args_ok` (private helper; public
  callers normalise alpha first).

## Confirmed: huge int leaks OverflowError

Local `float(value)` conversions catch only `(TypeError, ValueError)`:

- `cage/experiments.py` capacity/efficiency companions around the
  `accuracy_by_seed` loops (`float(value)`, `int(seed)` + `float(value)`).
  `float(10**400)` raises `OverflowError`; the code intends to skip
  unusable values.
- `cage/experiments.py` `_run_child_probe` loss list conversion.

## Open / lower priority

- `training_curve_verdict`: malformed `rel_tol` / `grad_norm_explode`
  raise `TypeError`; NaN/complex accepted silently. `train_model`
  `grad_norm_explode` unvalidated.
- `selection_at_fraction`: float32 tensor `0.1` gives `k=2` for n=10
  while Python `0.1` gives `k=1` (strict 4-ulp snap).
- `_CalibAttn.forward` scratch sizing assumes balanced query blocks;
  monkeypatched non-balanced blocks can overflow the scratch buffer.
- `standardized_proportion` 2D input semantics unconfirmed.
- `overfit_sanity_check` complex `steps` fails at `steps // 10` before
  `train_model` validation.
